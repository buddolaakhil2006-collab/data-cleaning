# Task 2 — Data Cleaning Audit

## Dataset and reproducibility

This report covers a deterministic, fictional retail line-item dataset generated by `src/generate_sales_data.py` (seed 42). It is synthetic, not company or customer data. The original `data/sales_raw.csv` is retained unchanged. Run `python src/generate_sales_data.py` to recreate it, then `python src/clean_data.py` to produce the clean output and this report.

## Transformations and rationale

- Removed **24 exact duplicate rows**. Exact duplicate records repeat the same line item and would double-count sales.
- Parsed `order_date` as a date and numeric fields as numbers with coercion. Coercion detected **9 invalid non-empty date strings** and numeric parse issues `{'units': 8, 'sales': 0, 'discount': 0, 'profit': 0}`; before/after dtype summaries are in `reports/before_after_profile.csv`. Invalid or missing dates (**30**) were dropped because an invented date would misstate monthly trends.
- Set impossible values to missing: non-positive units (**0**), negative sales (**6**), and discounts outside 0–1 (**0**).
- Imputed missing numeric metrics with their post-deduplication median and missing categorical labels with the most common observed label. This retains most records while limiting the impact of skew. Imputation counts and values: `{'units': {'count': 24, 'value': 5.0}, 'sales': {'count': 32, 'value': 108.16}, 'profit': {'count': 21, 'value': 16.89}}` and `{'region': {'count': 14, 'value': 'West'}, 'category': {'count': 13, 'value': 'Office Supplies'}}`.
- Used the 1.5×IQR rule to flag potential outliers in units, sales, and profit. Counts and cutoffs: `{'units': {'count': 2, 'lower': -1.5, 'upper': 10.5}, 'sales': {'count': 139, 'lower': -233.655, 'upper': 531.345}, 'profit': {'count': 162, 'lower': -41.714999999999996, 'upper': 88.085}}`. Flagged high sales/profit values were retained because large orders are plausible and clipping would distort financial totals. Review flags with source context before excluding any record.

## Quality result

The cleaned output has **1,773 rows**, **0 missing cells**, and **0 duplicate rows**.

## Limitations

The data are simulated; quality improvements demonstrate a reproducible procedure, not a claim about real sales. Median and mode imputations reduce data loss but can shrink variability. In a production setting, invalid rows should be reconciled with source systems and domain owners, and financial outliers should be reviewed individually.
